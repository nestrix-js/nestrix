## Settled design

- **One port**, default `4318` (`PORT`): `POST /v1/traces` (receiver), `GET /api/v1/*` (query API, same shapes as the embedded dashboard), `/` (the UI build from `@nestrix/ui`), `/login`, `/logout`.
- **Configuration** from the environment, validated at start (a bad value exits with a clear message): `DATABASE_URL` (required), `NESTRIX_INGEST_KEYS` (comma-separated keys, each at least 32 characters), `NESTRIX_INGEST_AUTH=none` (explicit opt-out for local demos, logged as a warning on every start), `NESTRIX_ADMIN_PASSWORD` (at least 12 characters; without it the UI and query API answer 503 and a log line says why; ingest still works), `NESTRIX_SESSION_SECRET` (optional; random per start otherwise), `NESTRIX_RETENTION_DAYS` (default 7).
- **Ingest auth:** `Authorization: Bearer <key>` or `x-nestrix-key: <key>`, compared in constant time. With neither keys nor the opt-out set, ingest answers 401 and a start-up log line says how to configure it. The example apps then need one variable, `OTEL_EXPORTER_OTLP_ENDPOINT`, with the compose file setting `NESTRIX_INGEST_AUTH=none` (acceptance: "one environment variable in each example app").
- **Receiver:** `application/x-protobuf` and `application/json`; `Content-Encoding: gzip` (and `identity`); 20 MiB limit (as the OpenTelemetry Collector; review of P5-01 lowered it from 64 MiB) applied to the compressed body and, separately, to the decompressed size (a gzip bomb is cut off while inflating, 413); caps on what a body decodes into, checked before decoding (413); a process-wide memory budget for requests in flight (503 with `Retry-After` when full); malformed body 400; invalid spans (bad id lengths, end before start, times beyond `int8` or more than a day ahead) rejected individually and reported through `partial_success`; `IngestBusyError` → 503 with `Retry-After`; over a per-key token bucket → 429 with `Retry-After`. Protobuf decoding with `@bufbuild/protobuf` and code generated from a pinned `opentelemetry-proto` tag, checked in under `src/proto/gen/` with the generation script; OTLP JSON has its own mapping (hex ids, string-encoded 64-bit integers, enum names or numbers, camelCase per the OTLP JSON spec). Responses use the request's content type.
- **Self-tracing:** the server imports `NestrixModule.forRoot({ ui: false, ignore: { routes: [/^\/v1\/traces\/?$/i] } })`, so with `OTEL_EXPORTER_OTLP_ENDPOINT` unset it traces nothing outward, and it never traces its own ingest route. (A regexp, not the string `'/v1/traces'`: a string matches the path exactly, but Express also routes `/V1/Traces/` to the receiver, and a test showed that request was traced.)
- **Storage** (PostgreSQL 18, Drizzle 0.45 for queries and schema types, hand-written SQL migrations for partition DDL, applied at start under an advisory lock): `resources` (hash-deduplicated attributes, `service_name`, `service_version`), `spans` partitioned by day on start time (ids as text, times as `bigint` nanoseconds plus a `timestamptz` partition key, attributes/events/links as `jsonb`, extracted columns `service_name`, `http_route`, `http_method`, `http_status`, `is_root`, `is_error`, `trace_type`, `user_id`), `traces` (one summary row per trace, upserted at ingest with its root's fields, span count, services and span names: the trace list reads it; root rule in `src/storage/traces.ts`), `services` (names and last seen, for `MetaResponse.services`), `route_minutes` (per minute of the span's end, service, method, route: count, errors, total and max, a 30-bucket latency histogram with the embedded route statistics' bounds; `src/storage/histogram.ts` estimates percentiles) written at ingest for every HTTP server span (kind server with `http.request.method`: each service's entry span, since OTLP does not say whether a parent is remote), `class_minutes` likewise for method spans (`nestrix.class`/`nestrix.method`; these are post-sampling here, and the UI says so). Rollups and summaries count only newly inserted spans, so a retried export is not counted twice. Partitions created for today and the next two days at start and daily; retention drops partitions older than `NESTRIX_RETENTION_DAYS`.
- **Query API**: every embedded route plus `service` as an optional filter on lists and statistics, `MetaResponse.services` (names seen in the window) and a `mode: 'embedded' | 'standalone'` field. The map across services (D-56): nodes per service plus each service's external targets; an edge from service A to B for every client/producer span in A whose child server/consumer span is in B.
- **Admin login:** `/login` serves a small server-rendered form (no inline script; the page has a strict CSP), `POST /login` checks the password in constant time, rate-limited per IP (5 per minute), and sets an HttpOnly, `SameSite=Strict` session cookie (`Secure` unless the request is loopback plain HTTP) signed with HMAC; `POST` checks `Origin`. The query API and UI require the session; the API never emits CORS headers. `/logout` clears it.

## Tasks

### P5-01 Bootstrap, configuration, receiver

Owns `apps/server/src/{main.ts,app.module.ts,config.ts}`, `src/ingest/**` (except `model.ts`, which it may extend compatibly), `src/proto/**`, `scripts/` for generation, and tests under `apps/server/test/ingest/**`. Uses an in-memory `IngestSink` in tests. Recorded payload tests: protobuf and JSON, gzip, partial success, a gzip bomb, an oversized body, wrong content type, bad auth, 503 and 429 paths. A small fixture generator using the official OTLP exporter (devDependency) to record real payloads.

#### P5-01 as built

- **Modules and tokens.** `AppModule.forRoot(config)` imports `ServerConfigModule.forRoot(config)` (global; `SERVER_CONFIG` in `src/config.module.ts` injects the frozen `ServerConfig` from `src/config.ts`), then `NestrixModule`, then `IngestModule.forRoot({ imports?, sink })`. The sink is the `INGEST_SINK` token (`src/ingest/tokens.ts`); today `{ useClass: MemoryIngestSink }` (counts batches and spans and keeps nothing; warns once). P5-02 changes that one line, e.g. `IngestModule.forRoot({ imports: [StorageModule], sink: { useExisting: PostgresIngestSink } })`. `createApp(config)` (`src/bootstrap.ts`) builds the app with `bodyParser: false` and `configureApp(app)` registers the JSON and urlencoded parsers for every path except the ingest path; tests build through `Test.createTestingModule` and call `configureApp` the same way (`test/ingest/helpers.ts`).
- **Order of checks:** auth 401 → rate limit 429 → media type and `Content-Encoding` 415 → declared `Content-Length` over the limit 413 (with `Connection: close`) → memory budget full 503 → body 413, 400 (bad gzip) or 503 (budget) → decoding caps 413 → decoding 400 → sink 503. After any early answer the unread body is read and discarded (up to 4 MiB and 5 s, nothing buffered, then the connection is destroyed) so the client gets the answer instead of a reset, which OTLP clients would retry.
- **Decoding caps** (review fix; `src/ingest/limits.ts`): before `fromBinary`, a walk of the protobuf wire format driven by the generated descriptors counts submessages and spans without allocating; before `JSON.parse`, a count of `{`, `[` and `,`; JSON spans are counted after parsing, before the JSON reader. Defaults: 100 000 spans, 400 000 submessages (or JSON objects), 1 200 000 JSON values per request; nesting 64. Protobuf unknown fields are skipped (`readUnknownFields: false`), since each would otherwise be kept as an object. Measured: an empty decoded span holds ~275 B, so the reviewer's 64 MiB of `0x12 0x00` (65 KB gzipped) decoded to ~2.2 GB per 16 MiB before the fix.
- **Memory budget:** 320 MiB per server, charged with the buffered body bytes plus 512 B per counted message and per span (plus 48 B per other JSON value), released when the request is done. Full: 503 with `Retry-After: 1`. A request whose charge exceeds the whole budget: 413 (it could never fit, so it must not be retried). A request at every cap is charged about 264 MiB, so it fits.
- **HTTP server:** `requestTimeout` 60 s, `headersTimeout` 20 s, `maxConnections` from `NESTRIX_MAX_CONNECTIONS` (default 1024), applied by `configureApp(app, config)`.
- **Per-span caps:** strings (attribute keys and values, including an attribute's JSON text, span and event names, status messages) cut to 16 KiB (UTF-16 units); 256 attributes per map (span, event, link, resource), 1 000 events and 1 000 links per span. What was dropped, plus the sender's own OTLP `dropped_*_count`, is recorded as `nestrix.dropped_attributes_count` (on the span, event, link or resource), `nestrix.dropped_events_count` and `nestrix.dropped_links_count` (on the span), only when non-zero. Links with invalid ids count as dropped.
- **Sink errors:** `IngestBusyError` → 503 with its `Retry-After` (clamped to 1–3600 s). Any other failure, synchronous or not → 503 with `Retry-After: 5` and a log line (throttled to one a minute), so a database outage is retried rather than dropped. Nothing calls the sink when no span survives validation.
- **Rate limit:** per key (per client address with `NESTRIX_INGEST_AUTH=none`), 100 requests per second, burst 200, one token per export request; buckets are kept in a map bounded at 10 000 and fail-closed (only expired entries are evicted; while full of live clients, new clients get 429, so rotating IPv6 prefixes cannot shed the limit), plus a global budget of 60 failed logins a minute across all clients (then every `POST /login` is 429 until the oldest failure leaves the window). Not configurable by environment yet (`ServerConfig.ingest.rateLimit`); P5-06's measurement says whether it needs a variable.
- **Validation:** a span is rejected for a trace id that is not 16 bytes or is all zero, a span id that is not 8 bytes or is all zero, a parent id that is neither empty nor 8 bytes, a start time of 0, or an end before its start. An all-zero parent id means a root. A link with an invalid id is dropped without rejecting its span. Kinds outside 1–5 map to `internal`.
- **Strictness of decoding:** `@bufbuild/protobuf` decodes proto3 strings strictly, so invalid UTF-8 in a protobuf body, or a lone surrogate in a JSON string, is a 400 for the whole request. The OTLP specification says decoders SHOULD substitute U+FFFD instead; the only switch for that in protobuf-es is the deprecated, process-wide `configureTextEncoding`, so it was not used. In JSON, an unknown enum name is ignored like an unknown field (protobuf-es with `ignoreUnknownFields`); enum names are accepted although OTLP 1.11 says senders MUST use numbers. Nesting is limited by protobuf-es (64 levels for protobuf, its default 100 for JSON): deeper is 400.
- **Mapped values:** attribute maps are null-prototype objects (a `__proto__` key is data); NUL characters become U+FFFD (PostgreSQL rejects them in `text` and `jsonb`); int64 values outside ±2^53 and non-finite doubles become strings; an array whose mapped items differ in type becomes JSON text.
- **Configuration extras:** `NESTRIX_INGEST_AUTH=none` together with keys is a start-up error; `DATABASE_URL` must be a `postgres://` or `postgresql://` URL; `NESTRIX_SESSION_SECRET`, when set, needs at least 32 characters; `PORT` is 1–65535 and `NESTRIX_RETENTION_DAYS` 1–3650. Errors never echo a value that may be secret.
- **Protobuf code** is generated by `pnpm --filter @nestrix/server generate:proto` (`scripts/generate-proto.mjs`) from opentelemetry-proto v1.11.1 (tarball SHA-256 pinned) plus a wire-compatible `google.rpc.Status` subset (`proto/google/rpc/status.proto`), into `src/proto/gen/` (checked in, excluded from Biome). Test fixtures are recorded with the official exporters by `pnpm --filter @nestrix/server record:fixtures`.

### P5-03 Query API over Postgres

Owns `apps/server/src/query/**`, its tests, and the protocol additions (`service` params, `MetaResponse.services`, `mode`), keeping `@nestrix/nestjs`'s mirror, drift checks and API spec copies green (the embedded store accepts `service` and filters by its own name).

#### P5-03 as built

- **Wiring.** `AppModule.forRoot(config, options?)` imports `StorageModule.forRoot({ databaseUrl, retentionDays })`, `IngestModule.forRoot({ sink: { useExisting: PostgresIngestSink } })` and `QueryModule.forRoot()`; self-tracing sets `integrations: { pg: false }`. `options.inMemory` (tests of the receiver only; `test/ingest/helpers.ts` sets it) swaps in the in-memory sink and leaves out storage and the query API, so ingest tests need no database.
- **Auth hook for P5-04.** `QueryController` runs `QueryGuardGate`, which delegates to the provider under `QUERY_GUARD` (`src/query/guard.ts`, a Nest `CanActivate`). The default is `DenyQueryGuard` (403 `forbidden`): the API is closed until something opens it. P5-04 passes its guard: `QueryModule.forRoot({ imports: [AuthModule], guard: { useClass: SessionGuard } })` (any provider shape without `provide`; `useExisting` works for a guard another module exports). A guard allows by returning `true`, denies by returning `false` (403) or throwing an `HttpException` (401, 503); `QueryExceptionFilter` renders it as an `ApiError`. Tests replace the token with `overrideProvider(QUERY_GUARD)` (`test/query/helpers.ts`).
- **Shapes and checks** are the embedded API's: the same parameter specs (copies annotated with `@nestrix/protocol`'s spec types in `src/query/params.ts`), 400 for unknown, repeated, malformed or out-of-range parameters and `before` with `after`, 404 for an unknown trace, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, no `Access-Control-*`.
- **Traces:** from `traces`, newest first by `seq`; cursor `t<seq base 36>` does not name the process, so it survives a restart. `service` filters by the trace's **root** service (the summary shows the root's fields); a trace that only touches a service is found through the trace view and the map. `error` is the root's error status (`traces.is_error`), narrower than the embedded definition (which also counts 5xx without an error status); `status=5xx` still finds those. `head` is the newest trace overall.
- **Errors:** error spans from `spans` newest first by (start time, trace id, span id); cursor `e.<start time, microseconds>.<trace id>.<span id>`. A span that arrives late with an older start time is not delivered to a poller already past it. `service` is the span's own service, `route` the trace root's route.
- **Routes and classes:** `route_minutes` / `class_minutes` summed over the window (merged across services unless `service` is given), percentiles from the summed histograms; own time from the stored method spans started in the window minus their direct children. Class counts are post-sampling (the UI must say so, P5-05). `methodsEnabled` is true when the window has any method rollup.
- **Map:** nodes `service:<name>` (kind `app`) for services seen in the window, plus each service's external targets (same node rules as the embedded map; edges `service:<name>` to the target). A client or producer span whose child server or consumer span is in another service is an edge `service:A` to `service:B` and not an external target. With `service`, the map holds that service, its targets and the services it calls or is called by. Percentiles are histogram estimates. At most 200 nodes; least-called targets fold into `other:overflow`.
- **Meta:** `mode: "standalone"`, `services` (seen within the retention window, sorted), `sampling: { owner: "host", rate: null }`, store counts from the database (`count(*)`, reused for 5 s; bytes from the partitions' sizes; the limit and eviction fields are 0), `statistics.sinceUnixMs` the oldest route rollup. `TraceResponse` has no per-span service field; P5-05 may need one for the trace view of a cross-service trace.

### P5-04 UI hosting and admin login

Owns `apps/server/src/ui/**`, `src/auth/**`, their tests. Serves `@nestrix/ui`'s files by its manifest (as `packages/nestjs/src/dashboard/assets.ts` does), with the dashboard's CSP.

#### P5-04 as built

- **Two layers, default deny.** `configureApp` mounts `AdminAuth.middleware()` (`src/auth/admin-auth.ts`) with `app.use()` first, before the body parsers and every Nest route, so it sees every request, matched or not. Only these raw paths pass without a session (anchored, case-insensitive, optional trailing slash, as Express routes them): `/v1/traces`, `/login`, `/login.css`, `/logout`. Everything else, `/`, `/assets/*`, `/api/v1/*`, unknown paths and any controller added later, needs a session: `/api` and `/api/*` answer 401 JSON (`{"error":{"code":"unauthorized",...}}`), other `GET`/`HEAD` answer `303 Location: /login`. Behind it, `AdminAuthGuard` (`APP_GUARD`, so global) lets a controller run only for a request the middleware stamped (private symbol): `session` for any controller, `ingest` only for `IngestController`, `login` only for `AuthController`; an app built without `configureApp` refuses every controller. **The query API (P5-03) needs no wiring:** any controller under `/api/v1` is covered by both layers (`test/auth/coverage.test.ts` registers a stand-in from another module). Tests that call the API sign in with `test/auth/helpers.ts` (`signedCookie()` or `loginCookie()`).
- **Session.** Cookie `nestrix_admin_<localPort>=v1.<exp>.<nonce>.<hmac>`: HMAC-SHA256 with a key derived from `sessionSecret`, SHA-256 of the admin password and a random value drawn once per process (changing the password ends every session, and so does **restarting the server**, even with a fixed `NESTRIX_SESSION_SECRET`: logout revocations live in memory, so a signed-out cookie must not revive after a restart). The cookie name carries the raw socket's `localPort`, as the embedded dashboard's does (architecture 4.7), because cookies are shared across ports on one host, 8 hours absolute (`Max-Age=28800`), `HttpOnly; SameSite=Strict; Path=/`, `Secure` unless the request is plain HTTP to a loopback `Host` with no forwarding header (decided by `Host`, not the socket peer: in Docker the peer of a browser on the host is the bridge gateway). `/logout` revokes the nonce in a bounded in-memory list until it expires.
- **`POST /login`.** Order: password configured (503) → `Origin` equals the single `Host` (scheme-agnostic, so a TLS proxy that keeps `Host` works; missing, `null`, other host or port → 403) → per-client limit, 5 attempts per sliding minute, every attempt counted, keyed by socket address (IPv6 by /64; never a forwarding header), map bounded at 10 000 → password, SHA-256 of both sides compared with `timingSafeEqual` (401) → `303 Location: /` (fixed target). Behind a reverse proxy all visitors share the proxy's limit, and the proxy must pass `Host` through (`proxy_set_header Host $host`) or `Origin` will not match.
- **Other requests.** `Sec-Fetch-Site: cross-site` → 403 on every path but ingest. A method other than `GET`/`HEAD` needs a same-origin `Origin` even with a session (403), which also refuses CORS preflights. The middleware sets `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `X-Robots-Tag`, `Cross-Origin-Resource-Policy: same-origin`, the dashboard CSP and `Cache-Control: no-store` on every non-ingest response (controllers may override), and wraps that response's `writeHead` so no `Access-Control-*` header goes out from a CORS layer registered after `configureApp` (tested with `app.enableCors()`). `createApp` itself registers no CORS layer (tested: `OPTIONS /api/v1/meta` answers 403 with no `Access-Control-*`); a CORS layer registered before `configureApp` is not covered by the wrapper.
- **Query API guard (integration with P5-03).** `AppModule` passes `QueryModule.forRoot({ guard: { useClass: SessionQueryGuard } })` (`src/auth/query-guard.ts`): it opens the query API only for a request the middleware stamped `session` (else 401), behind the middleware and the global guard. `test/query/helpers.ts` boots the full server with an admin password and sends `signedCookie()`; `AppModule.forRoot(config, { inMemory: true })` (no Postgres, no query API) serves the auth, UI and receiver tests. `ApiErrorCode` gained `unauthorized` and `unavailable`.
- **Without `NESTRIX_ADMIN_PASSWORD`** the UI and `/login` answer a 503 page, the API a 503 JSON (`code: "unavailable"`), and a start-up warning says how to set it; ingest is unaffected. With a generated session secret a log line says sessions end at restart.
- **UI** (`src/ui/`): `index.html` (`<base href="/">`, config `{"apiBase":"/api/v1","path":"","protocolVersion":1}`, `no-store`) at `GET /`, files at `GET /assets/<file>` (immutable), from an in-memory map built from `manifest.json` with size and SHA-256 checks; nothing is read from disk per request. A missing or broken build logs an error and answers 503. The login and 503 pages have no script and use `default-src 'none'; style-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`.
- **Left for others.** The protocol's `ApiErrorCode` has no `unauthorized` or `unavailable` (P5-03 owns the protocol). The UI has no sign-out control and does not send the user to `/login` when the API answers 401 after the session expires (UI work; a sign-out must `fetch('/logout', { method: 'POST' })`, since the dashboard CSP has `form-action 'none'`).
