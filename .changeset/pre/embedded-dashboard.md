Embedded dashboard. With `@nestrix-js/ui` installed (an optional peer of `@nestrix-js/nestjs`, same version), `NestrixModule` serves a read-only dashboard at `/_nestrix` from inside the application, on Express, Fastify and platform-node: recent traces, one trace's spans, errors, and per-route statistics counted before sampling. Routes sit outside the global prefix and versioning and are registered with the adapter's own `get` in `onModuleInit`; every response is written to the raw response with the dashboard's own Content-Security-Policy and no CORS headers, whatever the host's CORS configuration. By default (`ui: 'auto'`) it is served only when `NODE_ENV` is `development` or unset, to loopback requests without forwarding headers that carry the startup token: open the link Nestrix logs once the application listens. `ui: { enabled: true, auth }` serves it in any environment behind a token or a custom `authorize(request)`. Dashboard requests are not traced, and a host route that shadows the dashboard is logged once. `ui.startupToken: false` opts out of the startup token (a same-host reverse proxy then exposes the dashboard when `NODE_ENV` is unset). A host that owns its OpenTelemetry SDK adds `nestrixSpanProcessor()` to its `spanProcessors` to feed the dashboard. The new `store` option (`maxTraces`, `maxBytes`) bounds the in-memory store, oldest trace evicted first. Route statistics are counted before sampling, and the error list holds spans with error status (5xx; a thrown 4xx is not an error).
