Database and cache spans (level 3), with no setup and no Node flags. `pg` queries are traced whenever `pg` is installed (`integrations.pg: false` turns it off): client and pool, promise, callback, `pg-cursor` and `pg-query-stream`, including a nested `pg` copy an ORM such as MikroORM loaded at import time or in a provider factory (a copy first loaded during a request is not traced). A span covers the query only, not the wait for a pool connection, and lands in the trace of the request that issued it even when the pool is contended; a pool that cannot connect records an error span. `mysql2` (`integrations.mysql2: true`) and `ioredis` (`integrations.ioredis: true`) are opt-in, because once anything subscribes to their tracing channels mysql2 swallows an error from an event-emitter query with no `'error'` listener and ioredis swallows the rejection of a failing command nobody awaits, where either would otherwise crash the process. Redis commands that run outside any trace (connection handshakes, commands queued before the connection was ready) produce no span unless `integrations.ioredis.rootSpans` is `true`. Spans follow the current OpenTelemetry database conventions (`db.system.name`, `db.query.text`, `db.operation.name`, `db.namespace`, `server.address`, `server.port`). Statements are recorded with every literal replaced by `?`, comments removed and `IN (…)` lists collapsed, capped at 2,048 characters; a statement that cannot be parsed safely is replaced by a fixed placeholder text. For Redis only the command and its key are recorded. Bind parameters and values are never recorded.
